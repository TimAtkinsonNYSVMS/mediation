# Phase 1: migration (Knack → Airtable)

Make scenario **5021628 "Mediation portal - Migrate (Knack → Airtable)"** (folder 45165, on-demand). The blueprint is generated by `make/build-migrate-blueprint.mjs` into `make/migrate.blueprint.json`. Edit the generator, not the JSON.

Input `stage`. Run the stages in this order:
1. `facilitators`: Knack object_4 → People, upserted on Email.
   - Sets Roles = Facilitator, Active, Region, and Knack IDs = the object_4 record ID.
2. `complaints`: Knack object_1 → Complaints, upserted on Knack ID. A router then:
   - upserts the owner into People on Email (name, phone, address from Knack's concatenation fields) and links Owner;
   - finds the facilitator in People by Knack IDs and links Facilitator;
   - attaches the upload and the release form (Airtable copies each file from the Knack URL);
   - writes the feedback fields, rounding half stars up.
3. `updates`: Knack object_3 → Progress Updates, upserted on Knack ID.
   - Finds the complaint by Knack ID; updates with no complaint are skipped.
   - Links the author (the Knack "Mediator", object_4) by Knack IDs and attaches the document.

Every write is an upsert, so any stage can be rerun. Rerun `complaints` then `updates` to pick up anything that changes in Knack before cutover.

## Gotchas
- People.Knack IDs holds the **object_4 (Facilitators)** record ID only. Owners are matched by email and carry no Knack ID.
- Roles: owners get no role. A pet owner's access comes from being linked as Owner on a complaint. Staff and Admin are set by hand: Tim is Staff and Admin, Katie Smith is Staff.
- Rerunning `facilitators` resets Roles to ["Facilitator"], which wipes Staff for Tim and Katie. Set them again afterwards.
- The scenario should be switched **off** between runs.
